# user_profiles 조회 최적화 — 검토·계획·단점

**작성일**: 2026-01-30

---

## 1. 현재 구조 요약

- **전역 상태**: `App.tsx`에서 `userProfile` (useState)로 이미 앱 전역에 보관됨. Context API 추가 없이 이 상태를 “캐시”로 사용 가능.
- **조회 발생 시점**:
  1. 세션 복구/로그인 시 `fetchUserProfile(userId)` → `user_profiles` select 1회
  2. **프로필 모달 열 때** `authModal === 'profile'`인 useEffect에서 **매번** `user_profiles` select 1회 (제거 대상)
- **갱신 시점**: 언어 토글 시 `user_profiles` update 후 `setUserProfile(prev => ... preferred_language)` 로 이미 로컬 상태 동기화됨.

---

## 2. 수정 계획 (효율성 관점)

| 항목 | 내용 | 효율성 |
|------|------|--------|
| **1. 캐싱** | 프로필 모달에서 “매번 select” 제거. 이미 갖고 있는 `userProfile`만 사용. | 프로필 모달 열 때마다 읽기 1회 제거 → 호출 감소, 체감 속도 개선 |
| **2. 수정 시 동기화** | 서버 update 성공 시 기존처럼 `setUserProfile`로 전역 상태만 반영. (언어는 이미 구현됨) | 추가 select 없이 최신 상태 유지 |
| **3. 폴백** | 프로필 모달을 열었을 때 `userProfile == null`(초기 로딩 전 등)인 경우에만 `fetchUserProfile(user.id)` 호출. | 예외 상황에서만 1회 읽기, 정상 흐름에서는 0회 |

**구체적 코드 변경**:

- **App.tsx**  
  - `authModal === 'profile'`인 useEffect에서:  
    - `user?.id` 없으면 return  
    - **`userProfile != null`이면 return (캐시 사용, select 생략)**  
    - 그 외(전역 상태에 프로필 없음)에만 `fetchUserProfile(user.id)` 호출

---

## 3. 수정 시 서비스 사용상 에러·단점

| 구분 | 내용 | 대응 |
|------|------|------|
| **에러** | 별도 에러 없음. 기존 `fetchUserProfile`·`setUserProfile` 동작 유지. | — |
| **단점 1** | **텔레그램 연결 상태**는 봇/웹훅에서 서버만 갱신. 프로필 모달을 “캐시만” 쓰면, 다른 탭/봇에서 연결한 직후 같은 탭에서 모달을 열어도 “연결됨”이 바로 안 보일 수 있음. | 새로고침 또는 재로그인 시 최신 상태 반영. 필요 시 프로필 모달에 “새로고침” 버튼 추가해 수동으로 `fetchUserProfile` 호출 가능. |
| **단점 2** | **구독 상태·만료일** 등도 서버에서만 바뀌는 경우(결제/관리자 변경 등) 같은 탭에서는 캐시만 보이면 갱신이 늦게 보일 수 있음. | 위와 동일. 앱 재진입(새로고침/재로그인) 시 `fetchUserProfile`이 한 번 호출되므로 그때 최신화됨. |

정리하면, **불필요한 반복 select 제거**로 성능은 좋아지고, **서버에서만 바뀌는 값**(텔레그램 연결, 구독 등)은 “모달을 열 때마다 최신”이 아니라 “다음 로그인/새로고침 또는 수동 새로고침 시 최신”으로 보이게 됨.

---

## 4. 적용 여부

- **효율성**: 프로필 모달 오픈 시 읽기 제거로 호출 수 감소·반응 속도 개선에 유리함.
- **에러**: 구조상 새 에러는 없음.
- **단점**: 서버 단일 소스(텔레그램/구독)는 모달 첫 오픈 시점에는 캐시 기준으로 보이고, 필요 시 새로고침/재진입 또는 “프로필 새로고침”으로 보완 가능.

**적용 완료**: 위 계획대로 `App.tsx`에서 프로필 모달 오픈 시 select 폴백만 수행하도록 수정함. (전역 상태는 기존 `userProfile` 유지, 언어 변경 시 `setUserProfile` 동기화는 기존대로 유지)
