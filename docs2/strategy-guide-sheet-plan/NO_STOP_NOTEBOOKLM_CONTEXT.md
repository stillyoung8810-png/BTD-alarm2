## 0. 앱의 역할 한계 (Zero Assumption Rule) — 반드시 먼저 읽을 것

**이 앱은 증권사 HTS/MTS에 주문을 자동으로 넣거나 체결시키는 트레이딩 봇이 아닙니다.**  
무손절 다분할과 스마트 스플릿 **모두** 동일합니다.

| 앱이 하는 일 | 앱이 하지 않는 일 |
|---|---|
| 사용자가 설정한 **1회 매수 금액**, **분할 횟수**, **익절 목표**, **LOC/MOC 비율** 등을 바탕으로 **오늘의 매수·익절 가이드**를 계산해 화면에 보여줌 | 브로커 API로 LOC/MOC 주문을 대신 제출 |
| 거래 기록을 저장·집계해 **평단가·투입 원금·진행률**을 추적 | 시장가/지정가 주문의 실제 체결 보장 |
| RSI·이평선 정배열 등 지표가 충족되면 **그날 적용할 LOC 비율**을 자동 조정해 제안 | 사용자 대신 “무조건 매수” 실행 |

한 줄로 말하면, 무손절 다분할은 **“매일 저녁 HTS에 올릴 주문표를 대신 계산해 주는 스마트 계산기 + 투자 기록장”**입니다.  
사용자는 앱이 보여준 **가격·수량·비율**을 참고해 **직접** 증권사 앱에서 주문합니다.

**사용자 이득:** 복잡한 분할·비율·잔돈 처리를 매일 손으로 계산할 필요가 없고, “오늘은 LOC 2주 / MOC 1주”처럼 **투명한 숫자**만 보면 됩니다.

## 1. 전략 한 줄 정의

**무손절 다분할**은 손절(Stop Loss) 없이, 정해진 총 시드를 **N회 분할 매수**로 나누어 모으고, 목표 수익률에 도달하면 **전량 익절**을 안내하는 전략입니다.

- **총 시드(전략이 인지하는 규모):**  
  \(\text{총 시드} = \text{1회 매수 금액} \times \text{총 분할 횟수}\)
- **하루 예산:** 사용자가 포트폴리오에 입력한 **1회 매수 금액** (`dailyBuyAmount` / `oneTimeAmount`)이 그날 쓸 수 있는 **일일 예산**입니다.
- **두 갈래 매수:**
  - **LOC (평단가 매수):** 보유 **평단가**에 지정가 매수 → 가격이 내려올 때만 체결되어 평단 방어.
  - **MOC (분할 매수):** 당일 **현재가 × 1.15** 안전 버퍼로 수량을 먼저 확정 → “오늘 분할 몫은 어느 정도 확보”하는 역할.

## 2. 사용자가 설정하는 값 (포트폴리오 생성 시)

| 설정 항목 | 의미 | 사용자 이득 |
|---|---|---|
| **대상 종목** | 한 포트폴리오당 하나의 ETF/주식 | 계산이 단순하고 추적이 명확함 |
| **1회 매수 금액** | 매 분할 차수마다 쓸 예산 (총 시드는 × 분할 횟수) | “얼마씩 모을지”를 직관적으로 설정 |
| **총 분할 횟수 N** | 몇 번에 나눠 매수할지 | 급하게 몰아넣지 않고 분산 |
| **익절 목표 수익률 (%)** | 평단 대비 몇 %에서 **전량** 매도 안내할지 | 목표가가 자동 계산됨 |
| **평단가 매수 비율 (LOC) (%)** | 일일 예산 중 LOC 쪽 **기본** 비중 | 방어 매수 vs 추격 매수 균형 |
| **RSI 조건 (선택)** | RSI가 기준 이하일 때 LOC 비율 프리셋 적용 | 시장 과매도에 맞춘 비중 조절 |
| **정배열 조건 (선택)** | 단기 이평 > 장기 이평일 때 LOC 비율 프리셋 적용 | 상승 추세에서만 비중 변경 |
| **예산 프리셋 칩** | 방어(LOC 70%) / 균형(50%) / 추격(LOC 30%) | 숫자 대신 성향 버튼으로 선택 |

프리셋 LOC 비율은 보통 **70% / 50% / 30%** 중 하나입니다.  
RSI·정배열이 **동시에** 충족되면, 매칭된 프리셋 중 **더 큰 LOC 비율**을 그날의 `appliedLocRatio`로 씁니다.

---

## 3. 그날 적용되는 LOC 비율 — `appliedLocRatio`

1. RSI 규칙 충족 → 해당 LOC 프리셋 후보 추가  
2. 정배열 규칙 충족 → 해당 LOC 프리셋 후보 추가  
3. 후보 없음 → `baseLocRatio`  
4. 후보 여러 개 → **가장 큰 LOC 비율** 선택  

`appliedLocRatio`는 **0 ~ 100%**만 허용됩니다.

---

## 4. 폭포수 자금 배분 (Waterfall Allocation) — 핵심 수학

정책: **MOC First, Remaining Budget to LOC**

| 기호 | 의미 |
|---|---|
| \(B\) | 일일 예산 = 1회 매수 금액 |
| \(r\) | `appliedLocRatio` |
| \(P_{\text{avg}}\) | 평단가 |
| \(P_{\text{now}}\) | 현재가 |
| \(f\) | 수수료율 (%) |
| **1.15** | MOC 안전 버퍼 |

- \(C_{\text{LOC}} = P_{\text{avg}} \times (1 + f/100)\)  
- \(C_{\text{MOC}} = P_{\text{now}} \times 1.15\)

**순서:**

1. \(B_{\text{MOC,base}} = B \times (1 - r/100)\)  
2. \(Q_{\text{MOC}} = \lfloor_{\text{safe}} B_{\text{MOC,base}} / C_{\text{MOC}} \rfloor\) — **MOC 우선 확정**  
3. \(B_{\text{LOC,remain}} = B - Q_{\text{MOC}} \times C_{\text{MOC}}\) — **남은 전체 예산**  
4. \(Q_{\text{LOC}} = \lfloor_{\text{safe}} B_{\text{LOC,remain}} / C_{\text{LOC}} \rfloor\) — **LOC에 잔액 싹쓸이**

**사용자 이득:** MOC에 쓰이지 않은 잔돈이 LOC(평단 방어)로 자연스럽게 흘러가 잔돈 낭비를 줄입니다.

**검증 예시:** \(B=100\), \(P=30\), \(r=50\%\) → **LOC 2주 + MOC 1주**.

## 5. 전략의 세 가지 상태 (States)

### 공통 지표

- **총 투입 원금** \(I\) = 해당 종목 누적 매수 원가  
- **총 시드** \(S = B \times N\)  
- **전략 진행률** \(\text{progressPct} = \mathrm{clamp}(I/S \times 100,\ 0,\ 100)\)  
- **차수 개념** \(T \approx I/B\) (`currentRound`)

### 상태 A — 첫 매수

- 보유·평단 없음 → LOC/MOC **미계산**, 자유 매수 안내만  
- \(T \approx 0\), 진행률 ≈ 0%

### 상태 B — 활성 분할

- \(I < S\) → 매일 LOC/MOC + **익절 목표** 라인  
- **0주도 표시** (display 전용; executable은 1주 미만 제외)

### 상태 C — 분할 완료

- \(I \geq S\) → **추가 매수 라인 없음**, 익절 + 완료 안내만

## 9. 스마트 스플릿(Smart Split) vs 무손절 다분할 — 상세 비교

두 전략은 **같은 앱·같은 다분할 철학** 안에 있지만, **매도 구조·설정 복잡도·위기 대응**에서 크게 갈립니다.  
전략 설명 UI에서 “무손절 = 스마트 스플릿의 단순 버전” 정도로 소개하는 것이 정확합니다.

### 9.1 한눈에 보는 포지셔닝

| 구분 | 무손절 다분할 | 스마트 스플릿 |
|---|---|---|
| **한 줄 정의** | 분할 매수로 모으고, **한 번에 전량 익절** | 분할 매수 + **2단계 익절** + (필요 시) **리스크 컷** |
| **투자 성향** | 규칙 단순, “끝까지 들고 가다 한 번에 판다” | 적극적, “수익을 나눠 실현하고 위기 시 방어 버튼” |
| **손절** | **없음** (이름 그대로 무손절) | 일상 익절과 별도로 **리스크 컷** 시나리오 존재 |
| **설정 난이도** | 낮음 (익절 % 하나 + LOC 비율 + 선택 칩) | 높음 (목표 수익률 A/B, 익절 비중, 리스크 컷 % 등) |
| **일별 카드 키워드** | 전략 진행률, 익절 목표 | 현금 사용률, 메인 익절, 중간 익절, (조건부) 위험 관리 손절 |

### 9.2 공통점 — “다른 전략”이 아니라 “같은 매수 엔진 계열”

2026년 기준 프로덕션에서 **매수 배분 수학은 동일한 폭포수 모델**을 공유합니다.

| 공통 요소 | 설명 | 사용자 이득 |
|---|---|---|
| **MOC First → LOC 잔액** | MOC 수량 먼저, 남은 일일 예산 전부 LOC | 잔돈이 평단 방어 쪽으로 흐름 |
| **MOC 15% 버퍼** | \(C_{\text{MOC}} = \text{현재가} \times 1.15\) | 오늘 분할 몫이 지나치게 0주로 잡히는 것 방지 |
| **LOC = 평단가** | 지정가는 보유 평단 | 눌릴 때만 추가 매수 |
| **RSI / 정배열 프리셋** | 조건 충족 시 `appliedLocRatio`를 70·50·30% 중 더 큰 값으로 | 매일 슬라이더 조작 불필요 |
| **첫 매수 자유** | 보유 전에는 “장중 자유 매수” 안내 | 첫 진입 타이밍은 사용자 판단 |
| **0주 표시** | 활성 구간에서 LOC/MOC 0주도 라인 유지 | “숨김 = 안 사도 됨” 오해 방지 |
| **앱 역할** | 계산기 + 기록장, 자동 체결 아님 | 두 전략 모두 동일 |

> **주의 (설명 UI용):** 예전 문서·구형 코드의 스마트 스플릿 **“고가 LOC / High LOC”** 표현은 deprecated입니다. 현재 스마트 스플릿도 무손절과 같이 **평단 LOC + MOC(15% 버퍼)** 2트랙입니다.

### 9.3 설정 항목 비교

| 설정 | 무손절 | 스마트 스플릿 |
|---|---|---|
| 1회 매수 금액 | ✅ | ✅ |
| 총 분할 횟수 | ✅ | ✅ |
| 대상 종목 | ✅ | ✅ |
| 평단가 매수 비율 (LOC) | ✅ `baseLocRatio` | ✅ `baseLocRatio` |
| RSI / 정배열 칩 | ✅ (선택) | ✅ (선택) |
| **익절 목표 수익률** | ✅ **단일** `takeProfitPct` | ✅ **목표 A** `targetReturnRate` + **중간 B** `intermediateReturnRate` |
| **메인 익절 비중** | ❌ (전량 익절이라 개념 없음) | ✅ `mainTakeProfitRatioPct` (예: 60%) |
| **중간 익절 비중** | ❌ | ✅ 나머지 물량이 중간 익절 (자동 분할) |
| **리스크 컷 비중** | ❌ **없음** | ✅ `riskCutRatioPct` (예: 20%) |

**사용자 이득 요약:**

- **무손절:** “익절 목표 하나만 정하면 된다” → 학습 비용 낮음.  
- **스마트 스플릿:** “얼마를 메인/중간으로 나눌지, 위기 때 몇 %를 팔지”까지 설계 → **수익 실현·방어를 세밀하게** 조정.

### 9.4 매수 로직 — 수식은 같고, “오늘 쓸 예산”만 다를 수 있음

두 전략 모두 핵심 함수가 같은 **3단계 폭포수**를 따릅니다.

1. `appliedLocRatio`로 이론상 LOC/MOC 예산 분할  
2. MOC 수량 먼저 확정 (`×1.15`)  
3. 남은 **전체** 일일 예산으로 LOC 수량 재계산  

**무손절 (`calculateNoStopExecution`):**

- 활성 구간에서 **항상** `oneTimeAmount` 전체를 \(B\)로 사용 (분할 완료 전).

**스마트 스플릿 (`calculateMultiSplitGuideState`):**

- 활성 구간에서 \(B = \min(\text{1회 매수금},\ \text{남은 시드 잔액})\).  
- 마지막 분할 구간처럼 **남은 돈이 1회 매수금보다 작을 때**만 그 잔액만큼만 매수 가이드를 계산합니다.

**사용자 이득:** 스마트 스플릿은 “시드 거의 소진” 상황을 **매수금 부족** 상태로 더 세밀히 구분합니다. 무손절은 분할 완료(`isSplitComplete`)까지는 매 회차 **풀 1회분 예산** 기준으로 안내하는 쪽에 가깝습니다.

### 9.5 매도·익절 — 가장 큰 차이 (설명 UI에서 반드시 구분)

#### 무손절: 단일 익절, 전량 청산 지향

- 활성·완료 구간 모두 **익절 목표 한 줄**:  
  \(\text{익절가} = P_{\text{avg}} \times (1 + \text{takeProfitPct}/100)\), **보유 전량**  
- **중간에 일부만 팔기** 같은 개념은 엔진에 없음 (사용자가 수동 매도 기록하면 진행률만 변함).  
- **리스크 컷 / 손절 라인 없음.**

**사용자 이득:** “목표가 도달하면 다 판다”는 **단순한 멘탈 모델**. 장중 흔들림에 덜 흔들리려는 사용자에게 맞음.

#### 스마트 스플릿: 2단계 익절 + 조건부 리스크 컷

**평소(활성, 예산 충분):** 매일 화면에 최대 3종 매도 가이드가 나올 수 있음.

| 라인 | 의미 | 계산 개요 |
|---|---|---|
| **메인 익절** | 목표 수익률 A% 가격 | 보유 수량 × `mainTakeProfitRatioPct` (예: 60%) |
| **중간 익절** | 더 낮은 B% 가격 | 나머지 물량 (예: 40%) |
| **위험 관리 손절** | ❌ **평소에는 표시 안 함** | — |

**위기(매수금 부족 또는 시드 소진):**

- LOC/MOC 대신 **“매수금 부족”** 안내가 나올 수 있음.  
- 이때만 **위험 관리 손절: N주** 라인 추가 (`riskCutRatioPct`만큼, 가격 라벨 없이 수량만).  
- 코드 주석: 리스크 컷은 익절과 **동시에 매일 집행하는 게 아니라 대체 시나리오**.

**사용자 이득:**

- 상승장에서 **중간 익절**로 현금 확보·심리적 승리 경험.  
- 하락·시드 고갈 시 **리스크 컷**으로 “최후 방어” 수량을 미리 계산해 둠 (실행은 사용자).  
- 무손절보다 **수익 실현이 잦고 규칙이 많음** → 대신 설정·이해 부담이 큼.

### 9.6 진행 표시·상태 머신 비교

분자·분모 수학은 사실상 동일합니다.

\[
\text{비율} = \frac{I}{B \times N} \times 100
\]

| 항목 | 무손절 | 스마트 스플릿 |
|---|---|---|
| UI 라벨 | **전략 진행률** | **현금 사용률** |
| 게이지 의미 | 총 시드 대비 얼마나 채웠는지 | 동일 (다른 이름) |
| 첫 매수 | `isFirstBuy` | `isFirstBuy` |
| 분할 완료 | `isSplitComplete` (추가 매수 중단) | `isSeedExhausted` (매수 가이드 중단) |
| 예산 부족 상태 | 별도 플래그 없음 (0주 표시로 처리) | `isLowBudget` → “매수금 부족” 문구 |
| 평단 오류 | — | `isDataError` → “평단가 정보를 불러올 수 없습니다” |

**사용자 이득:**  
- 무손절: “아직 N% 채웠다”에 **집중**.  
- 스마트 스플릿: “시드 대비 현금 사용” + **부족/오류/소진**을 더 촘촘히 구분.

### 9.7 일별 실행 카드 — 나란히 보면

**무손절 (전형적인 활성일):**

```
전략 진행률: 37.5%
평단가 매수 (LOC): $98.50 / 2주
분할 매수 (MOC): 1주
익절 목표: $115.00 / 120주
```

**스마트 스플릿 (전형적인 활성일):**

```
현금 사용률: 37.5%
평단가 매수 (LOC): $98.50 / 2주
분할 매수 (MOC): 1주
메인 익절: $110.00 / 72주
중간 익절: $105.00 / 48주
```

**스마트 스플릿 (시드 소진 또는 매수금 부족일):**

```
현금 사용률: 100%
매수 가이드: 매수금 부족
위험 관리 손절: 24주
(메인/중간 익절 라인은 보유·설정에 따라 유지될 수 있음)
```

### 9.8 철학·UX 메시지 차이 (카피라이팅 힌트)

| 메시지 축 | 무손절 | 스마트 스플릿 |
|---|---|---|
| 앱 소개 (생성 화면) | “조건을 맞추고, 유리한 가격에 차곡차곡” | “동적 비중·분할 익절·최후 손절 방어” |
| 핵심 약속 | **손절 없이** 모으고 **한 번에 익절** | **중간에도 수익 실현**, 위기 시 **리스크 컷** |
| 실패 시나리오 | 오래 눌리면 오래 보유 (손절 없음) | 리스크 컷으로 일부 현금화 시나리오 제시 |
| 적합 사용자 | 단순함·장기 보유·한 번에 정리 | 복리+중간 현금화·규칙 세밀 조정 원하는 사용자 |

### 9.9 누구에게 어떤 전략을 추천할지 (가이드 문구용)

**무손절 다분할을 추천:**

- 익절 조건을 **하나**만 관리하고 싶을 때  
- 매일 **LOC/MOC 두 줄 + 익절 한 줄**이면 충분할 때  
- **손절·부분 익절 규칙 없이** “끝까지 모았다가 목표가에 판다”는 멘탈 모델을 선호할 때  

**스마트 스플릿을 추천:**

- 상승 중에도 **중간 익절**로 수익을 일부 실현하고 싶을 때  
- 메인/중간 **수익률·비중**을 직접 설계하고 싶을 때  
- 시드가 바닥날 때 **리스크 컷 수량**까지 미리 보고 싶을 때  

**둘 다 아님:**

- “앱이 알아서 매수·매도한다” → **둘 다 해당 없음** (반드시 동일 문구로 정정)

### 9.10 설명 UI·NotebookLM 혼동 방지 체크리스트

| 흔한 오해 | 사실 |
|---|---|
| “스마트 스플릿만 MOC가 있다” | **둘 다** MOC + LOC 사용 |
| “무손절만 평단 LOC다” | **둘 다** 평단 LOC |
| “스마트 스플릿은 손절이 있다” | **일상 손절이 아니라**, 시드 부족/소진 시 **리스크 컷 시나리오** |
| “무손절은 중간 익절이 없다” | ✅ 맞음 — 단일 익절만 |
| “진행률 ≠ 현금 사용률” | 수식은 같고 **이름만 다름** |
| “고가 LOC” | 구형 용어 — 현재는 **MOC(15% 버퍼)** |

## 10. 전략 설명 UI / NotebookLM에 쓸 때 권장 톤

1. **항상 먼저:** 자동 매매가 아니라 **HTS용 계산기**임을 밝힐 것 (무손절·스마트 스플릿 공통).  
2. **무손절 강조점:** 단순함, 전략 진행률, 단일 익절, 무손절, 0주 투명 표시.  
3. **스마트 스플릿과 비교 시:** “매수 엔진은 비슷하지만, 스마트 스플릿은 **2단 익절·리스크 컷**이 추가된다”고 구분.  
4. **피할 표현:** “자동 체결”, “앱이 대신 매수/매도”, “고가 LOC”.  
5. **권장 표현:** “계산해 드립니다”, “참고 주문표”, “조건 칩으로 오늘 비율 조정”.
